# 0.19.0-beta.1

## Added

- Capability-negotiated ACP form elicitation for FreeSeek `ask_user`.
- ACP additional workspace roots with canonical root-aware path authorization.
- ACP `coder`, `craft`, `plan`, and `ask` session modes with durable `session/set_mode`.
- Protocol-level tests for elicitation negotiation, additional-directory authorization/resume invariants, and skills/multi-agent policy.

## Changed

- File, search, exec cwd, checkpoint and hook routing now resolve against the actual authorized workspace root rather than assuming the primary root.
- ACP session metadata persists canonical additional directories and current agent mode.
- ACP Skills and Multi-Agent exposure is host-policy driven. When Skills are disabled, the ToolContext no longer carries a SkillManager, preventing indirect sub-agent skill inheritance.
- ACP server session configuration/parsing moved into a dedicated module to retain the repository's 600-line hygiene gate.

## Security

- Resuming an ACP session cannot silently expand or replace its persisted additional-directory authorization set.
- `ask_user` is absent from the ACP tool surface unless the connected client explicitly advertises form elicitation capability.

## Validation status

- Pre-promotion implementation tree: `npm run check` 8/8 gates pass.
- Pre-promotion implementation tree: `npm test` 340/340 pass, 0 fail.
- Final beta.1 versioned tree is revalidated before tagging.
